# 数学方法、实现与实验状态

本文记录 2026-09-24 整理代码库时确认的边界，方便复现与继续开发。整理工作保留原始算法和历史实验参数；新增证明与图片不会自动修复原有程序。

## 证明覆盖什么

[数学稿](proofs/geometric_visibility_proofs.pdf)针对具有共同道路序号的嵌入 Frenet 道路带，在明确的完整事件、非退化及端盖处理条件下论证两阶段比较和完整可见域分割。证明中的关键是互不相交的凸直线横截面。

现有 `fov_extended.py` 使用离散采样、角度容差及最小距离等阈值。它体现原方法的计算结构，但没有提供全部事件不漏检、全部交点精确或数值误差保守性的证书。几何证明不能直接推广为整个车辆优化程序的闭环安全或递归可行性证明。

## 几何与绘图的对应

1. **未知区轮廓。** 原有 `build_unknown_zone` 返回 `[P,T,U,P]`。在精确射线对齐时三个点共线；真正的同侧盲区由切点至返回点的边界弧与径向截线共同围成。新增原理图画的是这一数学构造，不能视为该旧函数原样输出的区域。
2. **左右约定。** 核心 `fov_extended.build_boundaries` 与 `viz_fov.build_boundaries` 对 named left/right 的法向使用不同。左右宽度不相等时，差异会影响道路几何本身。新说明图使用自身一致的定义；后续统一代码约定时，需要同时检查宽度、side 标记、缓存和 Frenet 正方向。
3. **曲线重建。** 缓存生成使用自然边界条件的三次样条，`plot_fov.py` 使用默认样条边界条件，`viz_fov.py` 使用离散中心线梯度绘制边界。这些重建不保证完全一致，尤其在端点附近。
4. **显示叠层。** 原有 `viz_fov.py` 的 `--sector` 是航向扇形绘图，`--track_expand` 是视觉扩宽，不能当作新增的可见性计算或传感器模型。有限视角需要另外进入数学模型。

说明图和动图依据原报告第 6.3 节及图 12 的构造重新计算示意几何，不复现 Monza 优化实验，也不宣称已验证所有退化场景。

## 缓存与规划接口

原缓存保存前沿位置的字段为 `final_fpv.s_fpv`；`OPT_LAPTIME_FULLFOV.py`、其 copy 以及 `solve_min_time_with_fov.py` 的 `fpv_s_on_grid` 读取 `final_fpv.s`。Opti 版本导入同一类辅助函数。这个不一致会使已有前沿落入默认查询距离分支，因此在修复并核对缓存字段前，不能把相应速度约束结果当作数学 FPV 的准确实现。

`OPT_LAPTIME_FULLFOV.py` 在构造规划带失败时会回退至道路边界，在前沿缺失时使用默认距离。求解器成功返回，并不单独证明预期 FOV 约束被使用。

当前中心线视点缓存也不直接认证优化后实际横向观察位置的可见域；若规划改变观察位置，几何更新或保守性需要另行处理。制动射线距离用于车辆停车保证，还需要实际制动路径、车辆形状和制动能力等条件成立，详见证明稿的控制接口部分。

## 哪些入口还不能直接复现

- `OCP.py`、`solve_min_time_with_fov.py` 引用 `../obstacle_avoidance` 及本库未收录的障碍物 CSV；`solve_min_time_opti_with_fov.py` 通过导入继承这些依赖。
- `solve_min_time_mpc_fov.py`、`viz_ocp_fov.py` 是空文件，不应当作已实现功能。
- `test.py` 和早期 FOV 文件引用旧的外部数据路径。
- 原缓存的 `source_csv` 是旧绝对路径；展示时使用 `--track Monza.csv`，避免依赖原作者机器目录。

本次曾成功执行 Monza 的一个核心几何查询及可视化参数帮助，完成 Python 文件语法解析；这些是入口检查，不替代精确几何对照或完整 OCP 复现。Python 3.10+ 是整个代码库的建议起点，因为部分历史优化脚本使用该版本引入的类型注解语法；目前未给所有依赖建立统一版本锁。
